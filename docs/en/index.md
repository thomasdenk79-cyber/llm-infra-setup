# Local LLM infrastructure (English summary)

One machine, one local model, no cloud calls. CachyOS, rootless Podman Quadlets,
NVIDIA RTX PRO 6000, vLLM runtime `flash-next-v3` serving
`Qwen3.8-Flash-Next-NVFP4`. The Pennyroyal/SGLang unit is kept as a reference
and does not run here; ZFS and PLE are planned but not enabled on this host.
State of record: `docs/status.md` (German, source of truth).

Contents: bring-up commands · components and ports · HTTPS entry points ·
credentials · further reading.

## Bring-up

Everything comes up with one repeatable command:

```bash
./setup.sh            # runs all phases, skips what is already done
./scripts/doctor.sh   # guided checks that print the exact next command
```

## Components and ports (loopback only unless stated)

| Component | Port | Note |
|---|---|---|
| vLLM runtime `flash-next-v3` | 30000 | unmanaged container, API on 127.0.0.1 only |
| vLLM metrics forwarder | 30001 | also binds host addresses (rootless pasta limitation, `docs/runtime.md`) |
| LiteLLM gateway v1.105.0 | 4000 | Virtual-Keys, fallback chain |
| Open WebUI | 3001 | chat, holds its own gateway key |
| Homepage portal | 3002 | also served over HTTPS names |
| Wiki | 3003 | rebuilt by timer |
| Grafana | 3000 | served under `/grafana/`, anonymous read role locally |
| Prometheus / Loki / Alertmanager | 9090 / 3100 / 9093 | Alertmanager intentionally has no receiver yet |
| Dozzle | 8080 | container logs, no upstream login |
| node_exporter / GPU exporter | 9100 / 9835 | |

Two Podman networks keep the inference plane and the observability plane apart;
Prometheus and the proxy `llm-proxy` are the components attached to both
(see `docs/adr/0009-scrape-across-networks.md`).

## HTTPS entry points (proxy `llm-proxy`, Caddy)

One managed Caddy container serves HTTPS on port 443, generated by
`scripts/74-setup-local-proxy.sh` from `config/proxy/Caddyfile.template`:

- Loopback (always): `https://homepage.localhost/`, `https://grafana.localhost/grafana/`
- LAN (only when `LAN_BIND_IPS` is set in `config/host.env`):
  `homepage`, `grafana`, `littlem`, `llm-direct`, `dozzle`, `direct-llm` under
  `.<LAN_DOMAIN>`; unknown names hit a 403 fallback and never reach a backend.
- The proxy publishes HTTPS 443; the unauthenticated vLLM forwarder on 30001
  is a separate trusted-LAN exception. Other backend ports remain loopback-only.

Addresses, protection model, Windows 11 client setup, teardown and the full
command list: [LAN HTTPS access](lan-access.md).

## Credentials

Gateway credentials live outside the repository under `~/.config/llm-infra/`;
`./scripts/show-credentials.sh` prints the operator-managed values. Never
commit them. The local Dozzle route is intentionally unauthenticated and must
remain restricted to the trusted private LAN.
